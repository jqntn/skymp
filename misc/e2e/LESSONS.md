# Lessons of the e2e loop

Facts about the engine, the server, and the harness. Add one after each ENV, each flaky result, and each fix that needed more than one try.

## Harness

- In low-cost mode, `skse64_loader.exe` to in-world takes about 10 s. A full S0 run is about 20 s.
- The client logs in automatically with the `profileId` of `skymp5-client-settings.txt`. No key press is needed.
- A new profile id spawns the player with RaceMenu open, and SkyrimPlatform cannot close a menu. `ctx.character(engine)` in `setup` creates the server actor first, so the spawn system loads it and does not open RaceMenu.
- The driver gets the `[Script]` lines of skymp5-client through the `consoleMessage` event.
- The server log goes to stdout (spdlog). `server.log` in the run folder has it.
- SSEDisplayTweaks `FramerateLimit` does not apply in menus. `UIFramerateLimit` does. `My Games/.../SKSE/SSEDisplayTweaks.log` confirms both at 30, but the in-game counter still shows 40 to 50.
- Level 1 costs about 2 min: incremental build 42 s, `ctest -C Release` 45 s, `yarn test` 1 s.
- `ctx.character` only calls `mp.createActor`. It does not set the `questStages` of the start point or the `spawnPoint` property as `spawn.ts` does. A check of the first login, the quest log, or a respawn must set them itself or use a real first login.
- Two Skyrim instances run side by side when the second one starts from another folder (`build/e2e-game2`, a hard-link copy). The engine rejects a second instance from the same folder within about 1 s. No hook is needed.
- `Debug.quitGame` and `Win32.exitProcess` end the process without `DLL_PROCESS_DETACH`, so SkyrimPlatform `Detach()` does not run. The early exit of a rejected instance does run it.
- In S0b, the screenshot right after `ready()` can be black on the second engine. 10 min later it shows the world.
- The client always shows "LOAD ORDER WARNING ... could not receive server mod list" for 5 s: `getServerMods` asks the master API, which answers 400 in offline mode. The playtest server has the same warning.
- A second engine costs about 10 s more to boot. S0b runs 10 min per run, so S0b alone takes 32 min of each full run.
- `mp.set(actor, "locationalData", { cellOrWorldDesc, pos, rot })` teleports a player across cells. A client `setPosition` into another cell is rejected and teleported back.
- Editor locations: Alvor 0x13482 and Gerdur 0x13489 are in their house interiors, Hadvar 0x2bfa2 is at Helgen (20044, -79479). The ESM scan in the probe (`mp.lookupEspmRecordById` over 0..0x110000) takes 6 s.
- The unit test `GetPartOne()` clears `bannedEspmCharacterRaceIds`. A test of the race filter must restore `WorldState().bannedEspmCharacterRaceIds`.
- MQ101AlduinREF does not resolve to AlduinRace through its template, so it is not a test of the ban. The mannequin 0x1028fd and the undead dragon 0x83588 are.
- `pathToReference` in a small interior stalls when players stand in the way. `translateTo` 200 units on the hoster gives a sure movement for a sync check.
- A server crash shows as "fetch failed" in a check. `server.log` ends with `[e2e] server exited with code N`; 3221225477 is an access violation.
- S1.1 had two ENV "engine N driver did not answer in 15 s" in a full run right after S0c, and none in 4 runs alone. A driver timeout now names the check line, and each retry keeps its own run folder (`n-retryK`).
- Game time is real UTC time plus `hoursOffset` in the client settings. The runner sets it per check (`gameHour`, default 12). At 12:00 Alvor's family wants to go out and refuses dialogue in the house; at 02:00 in a house, the owner can attack a trespassing player. The Sleeping Giant Inn (Orgnar 0x13486, Delphine 0x13485) is public at all hours.
- `keepOffsetFromActor` and `setDontMove` on an NPC block dialogue: the NPC targets the player but the Dialogue Menu never opens. Releasing the hold after the activation is too late. Standing puppets now have no offset hold; `translateTo` keeps their position.
- An NPC's AI can target the player with a greeting (`getDialogueTarget() == player`) without a dialogue. Only `isInDialogueWithPlayer()` means a real dialogue.
- Calls that are harmless on `placeAtMe` clones break real actors: `clearKeepOffsetFromActor` every frame on a hosted actor and `setOpen(false)` every 133 ms stopped dialogue on a seated NPC.
- `node misc/e2e/run.js --no-l1 --check <file>` runs an ad-hoc diagnostic check script under the id `adhoc`.
- The runner starts each game on a hidden Windows desktop (`skymp-e2e`, `desktop.ps1`), muted (`fAudioMasterVolume=0`). Rendering and `PrintWindow` work there. `--visible` uses the normal desktop.
- The cursor was locked to the hidden game window by SSEDisplayTweaks `[Window] LockCursor=true` and by DirectInput exclusive mouse. The runner sets `LockCursor=false` and Skyrim.ini `[Controls] bBackgroundMouse=1` for a run. The cursor clip then stays the full screen from launch to in-world.
- A runner that dies mid-run (here the PC slept for 6 h) leaves the ini files changed. The next start of `run.js` restores them, and kills the processes in `pids.json`. A stale runner can still hold port 7793.
- The seated Orgnar sometimes ignores a scripted `activate` (1 in 6 alone, 3 in 6 on the hoster after the other player talked first). A second activation after 10 s always worked.
- Once in a full run, engine 2 exited about 11 s after the launch at the start of S0b, with no client or crash log; the retry passed. Watch for a repeat.
- `server exited with code 1` at the end of a run is the runner's `taskkill /F`, not a crash.
- `enableAI(false)` on a puppet stops greetings, NPC chatter and combat, and player dialogue still opens. `resetAI()` first clears a dialogue target set before the actor became a puppet. With AI off, `keepOffsetFromActor` no longer animates: the client drives the puppet's graph with `moveStart`/`moveStop` and the `Speed` and `Direction` animation variables from the hoster's movement.
- The old offset hold left puppets walking in place: the puppet's `Speed` was 62 while the hoster's NPC stood.
- An engine can exit before its driver connects, with no log (seen right after a client install). `ready()` relaunches it up to 2 times.
- Teleporting both players straight from the Helgen exit to Hadvar at Helgen left Hadvar not loaded on engine 1 for 120 s; going through Alvor's house first works.
- A FormView is destroyed and created again when the player changes cell during a teleport. Any state it restores on destroy (here AI on) is live for a moment: Orgnar greeted the player in that moment and kept the target frozen once AI was off again. `resetAI()` and disable/enable do not clear that target.
- Each build gives every file of the client dist a new time in the game folder, so the old mtime sync copied about 400 MB (CEF included) into `build/e2e-game2` before its first launch. In full runs engine 2 then exited early 3 launches in a row. The runner now re-links each changed file (a fresh hard link per run), so engine 2 always has the current files and no new data.
- When engine 2 exits early, its skyrim-platform.log (shared file, rewritten at its start) ends after "NirnLab loader ... API version is ok": it dies around WinMain, where the engine rejects a second instance. The SKSE logs in My Games are shared by both engines, so read them with care.
- One hidden desktop per engine (`skymp-e2e-<n>`) fixed the engine 2 early exit: the full run at 13:56 had no relaunch, where 3 of the runs before it with one shared desktop did. The second-instance check looks for the first window on the same desktop.
- A hoster sends `SpeedSampled` as the NPC speed, and it decays for about 1 s after the NPC stops. The client's lag prediction (`speed * 0.2` ahead) then drove the puppet up to 69 units past the stop point (S1.1, Hadvar), and it snapped back about 1 s later. Real ESP puppets now skip that prediction.
- The game is French: base names are localized or empty (the smithing workbench is "Établi"), so never find refs by name. `mp.lookupEspmRecordById(id).record` in a probe gives the type and editorId (0x2c308 is RiverwoodBlacksmithWorkMarker, 0x133c8 is RiverwoodAlvorsHouse).
- `setPosition` on a puppet is not visible in the same driver call, and a translateTo in flight can undo it before the next sample. Call `stopTranslation()` first and read the position over the next frames (`sp.once("update")` in a promise; the driver awaits promises).
- A puppet with AI off opens the dialogue and shows its greeting, but the greeting never ends and no topic gets an answer (S1.5). The client turns AI on while the puppet is in dialogue with the local player. S1.2 only checked that the menu opens, so it missed this.
- Dialogue topics can be picked without key input: `sp.Ui.setInt("Dialogue Menu", "_root.DialogueMenu_mc.TopicList.selectedIndex", 0)` then `sp.Ui.invokeBool(..., "_root.DialogueMenu_mc.onSelectionClick", true)` once the greeting subtitle is empty; `onCancelPress` closes the menu. Text fields read fine with `getString`; numeric fields come back empty.
- Server Papyrus: `"archives": [<abs path to Skyrim - Misc.bsa>]` in the server settings gives the VM all vanilla scripts. A check sets it with `settings` in its module. `"logLevel": "trace"` logs every Papyrus event, method call and property set (numPillarsSolved, numRingsSolved), which makes script progress testable from server.log.
- The server sends OnInit/OnCellLoad/OnLoad to a ref only when a player-profile actor subscribes near it. `mp.createActor` without a profile id never triggers it; a bot that logs in (`loginWithSkympIo`) and is moved with `mp.set(actor, "locationalData", ...)` does. Script states (`GetState` through `mp.callPapyrusFunction`) are readable from the probe.
- With a bot as the only listener, `PlayAnimationAndWait` waits its 15 s timeout for a client reply, so a pillar or ring stays busy for 15 s after each turn.
- SkyrimPlatform hides its own synchronous native calls from hooks: `CallNativeApi` sets `Override`, and `OnSendAnimationEventEnter` returns early while it is set. So `ref.playAnimation(...)` from JS never reaches `hooks.sendAnimationEvent`; a latent call (`playAnimationAndWait`) takes the promise path without `Override` and does, like a Papyrus script's call. Hook handlers can use closures and `globalThis`.
- Registering a `sp.hooks.sendPapyrusEvent` handler from JS (even filtered to one ref id) froze the game: the driver never answered again. Avoid that hook; `hooks.sendAnimationEvent` works.
- A JS synchronous native call runs under `Override`, so the client's Papyrus event block is skipped for the events it raises: `lever.activate(player)` from JS ran the lever's own script on the client. Do not mistake that for the normal client behaviour.
- Parent-activation-only refs (XAPD flag 1, e.g. the BFB gate) raise no TESActivateEvent for a caster that is not one of their activation parents.
- SP `Quest.getAlias(id)` returns null for every quest on the client (MS13, MQ103 at stage 5). Use `ref.getNumReferenceAliases()` / `getNthReferenceAlias(n)` (SKSE) from the item ref instead; `dropObject` gives the ref of a persistent inventory item.
- A server `mp.set(container, "inventory", ...)` on an ESP container in the player's neighbourhood did not change the client's container within 4 s. The client applies a container inventory on CreateActor props and on UpdateProperty for ESP refs, so the server apparently does not send it on that set.
- Step checks run Catch2 tags through `ctx.unit("[id]")` (cwd `build`, `server: false`). After a C++ test change, `cmake --build . --config Release --target unit` in `build` takes about 2 min; L1 does the same plus ctest.
- `near` and `far` are macros on Windows (windef.h); do not use them as names in C++.
- S1.1: an NPC's own AI can walk it back after the test's translateTo (Hadvar ended 87 units from the start), so "moved" means the farthest point from the start, not the end point.
- A gamemode property made with `mp.makeProperty` (neighbour-visible, updateNeighbor code) and set on Alvor with `mp.set` showed no effect on either engine (display name, actor value, globalThis all unchanged), while `isHostedByOther` reaches the same FormViews. Cause not found; do not rely on custom properties for ESP NPCs until this is understood. Also, `printConsole` from the client plugin does not reach the driver's log, and `globalThis` writes from the client were not visible to the driver.
- A red check of a client fix: revert the line, `run.js --only L1,<id>` (L1 rebuilds and installs the client), expect FAIL, then restore and rebuild before anything else.
- Deferred kill keeps a pending kill once health reaches 0: endDeferredKill then kills the actor even if its health was restored above 0, and isDead() is still false right after endDeferredKill. Calling resurrect() right after endDeferredKill, in the same call, keeps the actor alive and no death reaches the server. Disable then enable (separate frames) also clears it.
- Locally spawned actors (placeAtMe from the driver) are deleted by the world cleaner within a second; test on real ESP NPCs instead.
- `Cell.getNumRefs(type)` filters by the base form type (actors: 43 NPC_) and does not list skymp's placed clones.
- A character made with `ctx.character` has no appearance, so other clients never render it (no clone). A check that needs one player to see another sets an appearance first (`mp.set(actor, "appearance", { raceId: 0x13746, ... })`), see 1B.3.
- A server-side revive of a hosted NPC raced with the hoster's next movement packet (still isDead) and killed it again; the server now ignores a hoster's death for 3 s after a respawn.
- A frenzied NPC (Aggression 3 + startCombat) lands a hit on a nearby clone in about half the runs within 45 s; 1B.3 reports ENV when no hit lands, and the retry usually passes.
- Running a check while the shell's working directory is inside `misc/e2e/out/runs/...` makes the runner fail with EPERM when it clears that folder.
- Packet history (`mp.setPacketHistoryRecording`) recorded nothing for a user in a check; do not rely on it.
- A run with `--no-l1` uses whatever client the last L1 installed. After a red run with the fix stashed, the next green run must rebuild (L1), or it tests the old client again. Order comparison runs old first, new last, so the new client stays installed.
- A stopped runner leaves its games running; they are listed in `out/pids.json` and the next run kills them.
- A real actor whose FormView applied its first movement before the player was in place (during the first load) is never moved again: the first apply ran while it was far and unloaded (a no-op), and later updates skip an unhosted actor. Seen with Hadvar at the Helgen exit on the old and the new client; teleporting away and back recreates the FormView and fixes it. Not yet a check.
- S1.1 "did not move on the hoster" also happens on the old client (one in two runs on 2026-10-12): the hoster's AI (combat, packages) can cancel the check's translateTo. It is a flaky check, not a 1B.4 regression.
- Driver round trips are not constant: in one old-client run they were about 560 ms in Alvor's house (133c8) at 35 fps, against 37-43 ms outdoors. S1.1 and S1.5 need 20 puppet samples in 11 s, so a slow round trip fails them ("only 17 puppet samples") without a code fault.
- Two engines take about 4.6 GB. Claude Code kills background commands when the system runs low on memory; a killed run leaves its games running (stop the ids in out/pids.json).
- An NPC that the client hosts without a first movement keeps its own state, often seated in furniture (sit state 3, bAnimationDriven). Moving a seated NPC with setPosition leaves it in the sit animation, so it does not walk; a push test on such an NPC says nothing about its AI. The old first movement translated NPCs to the server position, which stood them up.
- `Actor.pathToReference` resolves null at once in SkyrimPlatform and does not move the NPC (old and new client).
- `getNthReferenceAlias` and `Quest.getAlias` return null in SkyrimPlatform; the native `getReferenceAliasQuests(refrFormId)` returns the quest ids of a ref's aliases.
- Frenzied NPCs (Aggression 3) never attack the e2e player and only fight NPCs they see; a provocation that must cause combat adds `startCombat`.
- A red-proof patch that puts `return false;` at the top of a client method, or adds a condition that is always true, broke the L1 build. Patch the call sites instead (replace the call with a constant).
- A red-proof script that writes one patch, then throws on the next (a miss), leaves the first patch on disk. Check `git diff` after any failed red run.
- `run.js --check <file>` (adhoc) writes its evidence only to stdout, not to results.json or history.jsonl. Save the output to a file.
- Since 1B.3 the hoster sends its NPCs' activations to the server. `SendOpenContainer` sent the reply to the NPC's hoster, and the hoster's player then used the NPC's furniture. The server now sends it only to an activator with its own user.
- S1.2 failed 3 times in 4 runs between 23:52 and 00:12 UTC on 2026-10-12: Delphine in combat with the player, then twice no approach spot with line of sight. After that, the same build passed 5 runs of 5 (and a diagnostic copy of the check 3 of 3); with the HEAD server it passed 3 of 3. Treat it as a flaky period, like the slow-driver period, not a regression.
- SkyrimPlatform sets `Override` during every native call from JS, and the Papyrus event hook does not block events raised inside it. A driver `a.activate(player)` ran the target's OnActivate even with events blocked. To test the event gate, use a stimulus whose event the engine raises later: `startCombat` (OnCombatStateChanged).
- The client turns a puppet's AI off and stops its combat at each FormView update, so a check cannot put a puppet into combat, not even with an update handler that re-enables it.
- `Spell.cast(player, npc)` and `remoteCast` hit nothing. `player.doCombatSpellApply(spell, npc)` raises a hit event, but the projectile stops at the first ref in the way. Ambush actors sit in furniture (sarcophagi, thrones, ceiling webs), so a hit landed on the lid or a wall. An explosion from `placeAtMe` did nothing.
- The driver plugin has its own `sp` object. Replacing a function on it does not catch the client's calls, but native state (C++) is shared, so a getter native shows what the client set.
- `Cell.getNumRefs(62)` returned 0 in Bleak Falls Barrow; `getNumRefs(0)` with `Actor.from` lists the actors. The server record lookup gives the VMAD field, so a probe can find refs with a given script (masterAmbushScript: Variable01 goes from 0 to 1 and Aggression to 2 when the ambush ends).
- Spell form ids: 0x12fcc is Healing (not Firebolt); Flames 0x12fcd, Fireball 0x1c789, Frostbite 0x2b96b, IceSpike 0x2b96c, LightningBolt 0x2dd29, Sparks 0x2dd2a.
- A quest stage can have several log entries, each with its own conditions and fragment. MQ102 stage 15 runs Fragment_86 only if MQ102A stage 5 is done and Fragment_87 only if MQ102B stage 5 is done; with neither, the stage is set and nothing runs. A start log or a replay must set those stages first. The probe reads them from the QUST record: after each `INDX` (stage, uint16), a `CTDA` holds the operator (byte 0), the value (float at 4), the function (uint16 at 8, 59 = GetStageDone) and its parameters (uint32 at 12 and 16). The stage of each fragment is in the VMAD fragment list (stage uint16, log entry index uint32 at 4).
- Stage, scene and package fragments are method calls, not events, so `blockPapyrusEvents` does not stop them on any client.
- The world cleaner turns off the AI of every ESP actor that the client loads and does not host. The server does not load AlduinRace, UndeadDragonRace and Mannequin actors (`WorldState.h` `bannedEspmCharacterRaceIds`), so nobody can host them; the client now leaves their AI on. Before that, Alduin's MQ102 patrol never ended, and Ralof hid at the Helgen exit forever (package MQ102FriendWaitAtExitHide).
- SkyrimPlatform has no `isInInterior`; use `getParentCell()?.isInterior()`.
- A check with `engines: 0` starts only the server: a quick way to run probe-only diagnostics such as ESP record dumps.

- In a test game Hadvar runs MQ101HadvarHoldPosition (4679f; conditions GetGlobalValue(MQQuickstart 4679e) == 0 and GetStage(MQ101) < 20, hold near ref 46795). It fights keepOffsetFromActor: he stands still for minutes, or plays the walk animation without moving. MQQuickstart is a global; setValue(1) from the driver reads back 0. MQ101 stages move and strip the player, so they are no way out. A flee (Confidence 0, then startCombat(player)) moves him through combat AI; stopCombat and setDontMove(true) stop him (S1.6).
- CTDA function ids: 56 GetQuestRunning, 58 GetStage, 59 GetStageDone, 74 GetGlobalValue. The operator is the top 3 bits of byte 0 (0x00 ==, 0x20 !=, 0x40 >, 0x60 >=, 0x80 <, 0xA0 <=).
- A player placed at an offset from an NPC can land inside a building or in a river (the old S1.6 moves around the Riverwood mill), and the NPC cannot follow. Use fixed spots at measured ground heights: a server teleport at z + 300, then read z after 4 s.
- The server reverts a local player setPosition jump of 4096 units or more (MovementValidation); use a server locationalData teleport for long moves.
- A player teleported into a home before 8:00 trespasses (bounty 5) and the family kills the player. A check that needs the player inside sets the cell public first: `Cell.setPublic(true)` on the client before the server teleport.
- The driver's `sp` has no `Door` or `Static` class, and `Form.getType()` or `getName()` can throw "Bad call result 4" on some forms; wrap such probes in try/catch.
- A server door teleport of a hosted NPC is followed by a HostStop. A host claim with a location (1B.4) that the client sends before it applies the teleport moves the NPC back to the old cell on the server.
- The local engine runs NPC schedules off-screen: at 7:59 a new character's client had Alvor on the forge marker, Sigrid in her garden and Dorthe at her play spot, while the server still had all three in their house (the server only learns positions from a hoster). A client that moved them to the stale server position with `moveRefrToPosition` while the house was not loaded got them at shifted spots (Alvor -536,-125 for -515,-154) about half the time, and then one or more of them often stood still for minutes (with the player in view their dialogue target turned to the player). A hands-off control without hosting stalled too; an in-place teleport at load did not help. Since 2026-10-13 the first update keeps the local position (user decision), and nobody is pulled in.
- An NPC does not leave through a load door while the player stands near him on the same floor (seen up to about 500 units, with and without line of sight): his dialogue target turns to the player and he waits by the door for minutes. He uses the door about 3 s after the player goes a floor down. It happened with hosting and with a client that never touched him, so a schedule check keeps the player out of the NPC's way instead of following him.
- Every probe in an e2e diagnostic must be tried once before a long run: the driver lacks `sp.UI` (use `sp.Ui`), `sp.Door` and `sp.Static`, and `sp.storage["hosted"]` does not serialize into the driver (read hosters on the server with `mp.get(id, "hoster")`).
- Since the client position wins for an NPC that nobody hosts, a check must not send players to the server position of such an NPC: use `ctx.npcLocation(id, engine)` (the position the client has; the server position only as a fallback), and place an NPC on the clients (`moveRefrToPosition` through the driver) as well as with `mp.set`. Two clients start with their own copies at their own spots; the puppet snaps to the hoster within about 2 s, so a follow measure starts only once both agree.
- `exp-red`-style red runs build and install the reverted client; the next green run must rebuild (L1).
- The base of an ACHR in a probe: the NAME field of `mp.lookupEspmRecordById(id).record.fields` (4 bytes, little endian); `mp.get(id, "baseId")` gives 0 for ESP refs. Scan the ESM in chunks of 0x8000 ids, the probe call times out after 15 s.
- `ctx.restartServer()` kills the server process tree and starts it again with the same world folder; the clients reconnect on their own, and `mp.getUserByActor(actor)` is 65535 until the player is back.
- A server C++ red: build with `cmake --build . --config Release` in build/ and run with --no-l1 (L1 also runs the unit tests, which may fail on purpose), then restore and rebuild.
- The upstream unit test "Activate torch" (`unit/PartOne_ActivateTest.cpp:587`) sets a reloot time of 25 ms, so it fails when more than 25 ms pass between the activation and the next `Tick` (L1 failed once on 2026-10-13 at 21:40 on a branch with no C++ change). Rerun L1 before looking for a cause.
- Each `cmake --build` republishes `build/dist/client` as the rolling-release zip that playtest friends download (`PUBLISH_CLIENT_DIST`), so a red build publishes a broken client. Rebuild from HEAD after red runs, and do not run the loop during a playtest.
- When Steam is not running, each game launch starts `steam.exe steam://run/489830//`, which hangs, and the run is ENV (engine exited before its driver connected). `steamwebhelper` leaked to 39 GB after a day of runs; restart Steam when memory is low.
- `--only` without L1 does not build: after a code change, list L1 or run `cmake --build . --config Release` in build/ first, or the run tests the previous build (G1.6, 2026-10-14: a "two-frame reset" run measured the build before it). `--check` now stops when L1 fails, since an earlier `--check` ran on a stale client after a TypeScript error.
- A TypeScript type error fails the first `cmake --build` (MSB8066 on skymp5-client), but webpack still writes the bundle, and a second `cmake --build` then reports success without rerunning the client step (G1.6, 2026-10-14: a duplicate class field passed the second build and broke L1 later). After a client build failure, run `npx tsc --noEmit -p .` in skymp5-client before trusting a green rebuild.
- Key presses cannot be simulated faithfully on the runner desktops (G1.7, 2026-10-14). `sp.Input.tapKey` and keys injected into the DirectInput keyboard read or into `BSInputEventQueue` give no button event (the game does not read the keyboard of an unfocused window). `PlayerCharacter::ActivatePickRef` from a game-thread task and an Activate `ButtonEvent` sent through `BSInputDeviceManager` do activate, but miss 2 to 5 of 6 to 8 presses even on an NPC the engine hosts itself (the NPC's dialogue target becomes the player, no menu), more right after a `setPosition` or `setAngle` of the player. A check that needs the player's own key cannot use a single press as a measure; a visible run with input focus is untried.

- SP events that a native hook sends with `EventHandler::SendEventOnTick` reach JS in the tick context, where Papyrus-backed calls such as `Game.getFormEx` and `Actor.from` throw (G1.8, 2026-10-14: the handler stopped silently after its first line). Queue the event and handle it in an `update` handler.
- A dead actor with AI disabled opens no loot menu on `activate()`, with or without default processing; `openInventory(true)` still opens a ContainerMenu, and the same corpse with AI on opens normally (2A.1, 2026-10-14: puppet corpses). `enableAI(true)` has no effect on an actor that is already dead (the corpse stays AI-off), so the client opens such a corpse with `openInventory(true)`.
